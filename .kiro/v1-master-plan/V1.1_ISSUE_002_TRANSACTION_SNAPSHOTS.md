## Executive Summary

**Problem:** Transactions reference master data (Product, Unit, Category) by ID. When master records are edited, historical transactions show inconsistent data (old names with current units, etc.).

**Solution:** Snapshot relevant master data fields at transaction creation time.

---

## Context for AI Agent

### Current Behavior (Broken)
1. Create transaction: "Sell 5 pieces Fried Chicken" → stores `productId: abc123`
2. Edit product: Change name to "Crispy Chicken", change unit to "serving"
3. Old transaction now shows: "Crispy Chicken" (new name) with old quantity
4. Reports are inconsistent across time periods

### Required Behavior (Fixed)
1. Create transaction: Snapshot "Fried Chicken", "piece" at transaction time
2. Edit product: Master record changes
3. Old transaction still shows: "Fried Chicken" (snapshot) with "piece" (snapshot)
4. Reports are historically accurate

### Task 3: Backfill Existing Transactions (Migration Data Script)

**File:** `prisma/migrations/backfill-transaction-snapshots.ts` (NEW FILE)

**Purpose:** Populate snapshot fields for existing transactions using current master data

```typescript
/**
 * backfill-transaction-snapshots.ts
 *
 * One-time migration script to populate snapshot fields for existing transactions.
 * Run after the schema migration adds the snapshot columns.
 *
 * Usage: npx tsx prisma/migrations/backfill-transaction-snapshots.ts
 */

import { PrismaClient } from 'prisma/generated/prisma/client'

const prisma = new PrismaClient()

async function backfillTransactionSnapshots() {
  console.log('Starting transaction snapshot backfill...')
  
  // Find all transactions with missing snapshots
  const transactions = await prisma.transaction.findMany({
    where: {
      OR: [
        { productId: { not: null }, productNameSnapshot: null },
        { unitId: { not: null }, unitNameSnapshot: null },
        { categoryId: { not: null }, categoryNameSnapshot: null },
      ]
    },
    select: {
      id: true,
      productId: true,
      unitId: true,
      categoryId: true,
    },
    take: 1000, // Process in batches
  })
  
  console.log(`Found ${transactions.length} transactions to backfill`)
  
  let updated = 0
  
  for (const tx of transactions) {
    const updateData: any = {}
    
    // Load product snapshot
    if (tx.productId) {
      const product = await prisma.product.findUnique({
        where: { id: tx.productId },
        select: {
          name: true,
          sku: true,
          category: { select: { name: true } }
        }
      })
      
      if (product) {
        updateData.productNameSnapshot = product.name
        updateData.productSkuSnapshot = product.sku
        updateData.categoryNameSnapshot = product.category?.name ?? null
      }
    }
    
    // Load unit snapshot
    if (tx.unitId) {
      const unit = await prisma.unit.findUnique({
        where: { id: tx.unitId },
        select: { name: true, abbreviation: true }
      })
      
      if (unit) {
        updateData.unitNameSnapshot = unit.name
        updateData.unitAbbreviationSnapshot = unit.abbreviation
      }
    }
    
    // Update if we have any snapshot data
    if (Object.keys(updateData).length > 0) {
      await prisma.transaction.update({
        where: { id: tx.id },
        data: updateData
      })
      updated++
    }
  }
  
  console.log(`Backfill complete. Updated ${updated} transactions.`)
}

backfillTransactionSnapshots()
  .catch(console.error)
  .finally(() => prisma.$disconnect())
```

**Note:** This script uses CURRENT master data to backfill. It's the best approximation we have for historical data. Mark this as a limitation in documentation.

## Limitations to Document

⚠️ **Known Limitation:**
Backfill uses CURRENT master data as of backfill date. If a product was renamed before backfill, we cannot recover the original name. This is acceptable — backfill is best-effort.

Going forward, all new transactions will have accurate snapshots.
